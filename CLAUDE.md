# Coding rules
- Keep it simple: readable, idiomatic code over clever or optimized code.
- Prefer native array methods over manual loops.
- Use a well-maintained library instead of writing solved problems from scratch.
- Ask me before adding any new dependency.
- No abstractions, options or config that nothing uses yet.
- Follow the framework's idiomatic patterns.
- Run build, lint and tests before saying a task is done.

# Workflow
- Never commit or push to `main`. Work on a `feature/<name>` or `fix/<name>` branch and open a pull request into `main`.
